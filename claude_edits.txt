I found about 30 problems in acq4_to_nwb.py. I made no changes. Three of them stop the
conversion outright: no file is written unless you pass `-o`, every voltage-clamp protocol

## Step 1 — Fix the problems that crash or skip conversion

1. No file is written unless `-o` is given (lines 580-589). `if not self.overwrite or
   self.testmode: return outfilename` returns before converting whenever overwrite is off,
   even when the output file doesn't exist yet. The message on 583-586 also prints under the
   wrong condition and says "Testmode is true" when it isn't. `testmode` is never passed from
   `main()` or `ConvertFile` either, so `-t` does nothing. The intended rule is probably: skip
   if the file exists and overwrite is off; skip writing in testmode; otherwise convert.
2. Every voltage-clamp protocol crashes (line 892). `resolution=np.NaN` raises
   AttributeError: `NaN` was removed in NumPy 2, and the environment has 2.4.4. It should be
   `np.nan`.
3. Running the file directly runs a broken test (lines 1668-1670). The `__main__` block calls
   `test_weight_conversion()` instead of `main()`. That test calls `A2N.weight_with_units`,
   which isn't a method (it's a module-level function), so it crashes. The `uv run
   acq4_to_nwb` command is unaffected because it calls `main()`. Move the test into
   `tests.py` or pytest and restore `main()`.
4. The LED stimulus uses the wrong array axis (lines 1131 and 1146). `LED_Raw` has shape
   (sweeps, samples), so `[:, sweepno]` stores one sample from every sweep instead of the
   waveform for this sweep. It should be `[sweepno, :]`.
5. Laser site lookup can go out of range (lines 1059-1113). The result of
   `getScannerPositions()` (`scinfo`) is ignored. `sites` comes from `scanner_info`, which can
   have fewer entries than sweeps, so `sites[sweepno]` can raise IndexError. A related bug in
   acq4_reader.py:1630 makes this worse: `if target > ntargets` should be `>=`, otherwise the
   (rep, target) keys are off by one and repeated sweeps overwrite earlier ones.
6. Missing `type 2` raises KeyError (line 615). The code only checks for `type 1` before
   reading `cell_index['type 2']`.
7. Possible NameError on unset variables (lines 765-766 and 939). `datainfo` is only set
   inside a loop, and `sweepno` is used after its loop. If a protocol has no sweeps, both are
   unset. Use `len(...)` for the counter.
8. Exclusions are applied wrongly in `cvt()` (lines 1341-1350).
   - `protocols in ['all','All']` compares the list of protocols, so it is never true. It
     should test `exclusions[key]['protocols']`.
   - If only the slice key (`ds`) matches, `exclusions[dsc]` raises KeyError.
9. `check_conversion` can hit a NameError (lines 1520-1523). The bare `except` prints
   `results`, which may not be set, then calls `exit()`.

## Step 2 — Fix wrong data or metadata in the output

10. Timing is wrong (lines 654, 801, 821, 869, 895).
    - `timestamps_reference_time` is set to the time of conversion, not the time of the
      experiment.
    - Every series has `starting_time` set to the day's absolute epoch timestamp (about
      1.7e9 s). In NWB, `starting_time` is seconds since the reference time.
    - The fix is to use `session_start_time` as the reference and give each sweep its own
      timestamp minus the session start.
11. Holding potential is stored as a data offset (line 901). `VoltageClampSeries.offset` is
    added to the data when it is read back in physical units, so this shifts every recorded
    current. Holding belongs in metadata, not `offset`.
12. `subject_id` is not unique (line 609). The fallback is `dset[-2]`, which is the slice
    folder (for example `slice_000`), so different animals end up with the same ID. It should
    use the day folder (`dset[-3]`).
13. Sex values can be invalid (line 533). `.upper()` turns "male" into "MALE", but NWB and
    DANDI only accept M, F, U or O.
14. Age handling (`ISO8601_age` and lines 543-555).
    - The `~` and `?` suffixes it adds are not valid ISO 8601, so nwbinspector or DANDI may
      reject them.
    - The `[ish\?]{0,3}` pattern also accepts strings like "his".
    - Ages given in weeks, months or years are used as days when calculating date of birth.
    - A missing age silently becomes `P0D`.
15. Opto stimulus power is wrong (lines 851-858 and 925-932). `OptogeneticSeries` is a
    placeholder (`data=[70.0]`, `rate=1.0`). Its unit is watts, so this records 70 W (it
    should be 0.07 W for a 70 mW laser), and the LED gets the laser's value too.
16. Opto stimulus is stored as an electrical stimulus (lines 1077-1156). It is saved as a
    current- or voltage-clamp stimulus series with units of amperes or volts.
    - The opto recordings (`id + 10000`) are left out of `recordings`, so they aren't linked
      to the simultaneous or sequential tables.
    - The 10000 offset can collide with real IDs once a file has more than 10000 sweeps.
    - If a protocol has both laser and LED data, the LED overwrites the laser stimulus.
17. Laser data is the same for every sweep (line 1096). The reader keeps only the first
    sweep's Pockels cell trace. Both the laser and LED data are also re-read from disk for
    every sweep (the sweep count squared).
18. Clamp settings come from the last sweep (lines 765-766). Gain, holding and other settings
    are applied to every sweep.
19. `control` is misused (lines 778-781 and 797). NWB expects `control` to have one entry per
    data point. Here it gets two values, `[tstart, tend]`, as sample indices, while the
    description says they are seconds.
20. Mismatched `stimulus_description` values.
    - The CC response is always "Current Steps", even for LED and map protocols.
    - The VC response uses the cell folder name.
    - The stimuli use the protocol path.

- Cross-reference: DANDI reads slice_id and cell_id from a DandiIcephysMetadata object in
  lab_meta_data (ndx-dandi-icephys 0.4.0, on PyPI). It uses them in the file name
  (sub-X_ses-Y_slice-S_cell-C_icephys.nwb) and records the chain subject -> slice -> cell in
